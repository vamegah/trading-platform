# Requirements Document

## Introduction

This feature enriches the existing React 19 + Vite 7 frontend of the AI-powered trading platform with interactive financial charts and deeper data visualization. All major UI components are already scaffolded but currently display only text and numeric values. The enrichment installs `@tradingview/lightweight-charts` and integrates it into six target components — StockDeepDive, ExplainabilityPanel, BacktestViewer, PortfolioHealth, StressTest, and DiscoveryScanner — replacing or augmenting thin text rows with purpose-built financial charts. No backend changes are required; all data is already available through the existing `frontend/src/services/api.js` service layer.

## Glossary

- **Dashboard**: The React application shell defined in `frontend/src/App.js` that hosts all tab panels.
- **StockDeepDive**: The component at `frontend/src/components/StockDeepDive/index.js` that displays per-symbol signal analysis.
- **ExplainabilityPanel**: The component at `frontend/src/components/ExplainabilityPanel/index.js` that displays signal driver scores and risk language.
- **BacktestViewer**: The component at `frontend/src/components/BacktestViewer/index.js` that displays walk-forward backtest results.
- **PortfolioHealth**: The component at `frontend/src/components/PortfolioHealth/index.js` that displays live portfolio risk metrics.
- **StressTest**: The component at `frontend/src/components/StressTest/index.js` that displays scenario stress-test results.
- **DiscoveryScanner**: The component at `frontend/src/components/DiscoveryScanner/index.js` that ranks a user-defined stock universe.
- **ChartContainer**: A reusable React wrapper component responsible for mounting, sizing, and disposing a Lightweight Charts instance.
- **CandlestickSeries**: A Lightweight Charts series type that renders OHLC bars as Japanese candlesticks.
- **HistogramSeries**: A Lightweight Charts series type that renders volume or distribution data as vertical bars.
- **AreaSeries**: A Lightweight Charts series type that renders a filled line chart suitable for equity curves and probability areas.
- **AgentScoreChart**: A custom SVG or canvas bar chart component that visualises the seven AI agent contribution scores.
- **Lightweight Charts**: The `@tradingview/lightweight-charts` npm package (v4 or later) used as the sole charting library.
- **equity_curve**: The array of portfolio value floats returned by the `/backtest/walk-forward` endpoint inside the `full_walkforward_backtest` response.
- **component_scores**: The object of seven named agent scores (`fundamentals`, `technical`, `news_sentiment`, `macro`, `alt_data`, `debate`, `tax`) returned inside `recommendation.component_scores` by the signal orchestrator.
- **probability_distribution**: The object containing `up_5pct_20d`, `down_3pct_20d`, `flat_20d`, and `tail_loss_8pct_20d` probabilities returned by the signal orchestrator.
- **positions**: The array of per-symbol stress-test results (`symbol`, `current_value`, `stressed_value`, `pnl`, `pnl_percent`) returned by the stress-test engine.
- **OHLCV**: Open, High, Low, Close, Volume — the standard candlestick data format required by Lightweight Charts.
- **Simulated price path**: The deterministic price series generated by `_sample_price_path()` in the backtest engine, used as a proxy for historical OHLCV data until a live market-data endpoint is wired.

## Requirements

### Requirement 1: Charting Library Installation

**User Story:** As a frontend developer, I want `@tradingview/lightweight-charts` added to the project dependencies, so that all chart components can import from a single, finance-specific charting package without introducing conflicting libraries.

#### Acceptance Criteria

1. THE Dashboard SHALL declare `@tradingview/lightweight-charts` as a production dependency in `frontend/package.json` with a pinned major version (e.g., `"@tradingview/lightweight-charts": "^4.2.0"`).
2. WHEN the frontend build runs (`npm run build`), THE Dashboard SHALL complete without errors related to missing or unresolved chart library imports.
3. THE Dashboard SHALL NOT introduce any additional charting libraries (e.g., Chart.js, Recharts, D3) as part of this feature.

---

### Requirement 2: Reusable ChartContainer Component

**User Story:** As a frontend developer, I want a shared ChartContainer wrapper, so that every chart in the application mounts and cleans up its Lightweight Charts instance consistently without memory leaks.

#### Acceptance Criteria

1. THE ChartContainer SHALL accept `width`, `height`, and `options` props and render a `<div>` element that Lightweight Charts attaches to.
2. WHEN the ChartContainer mounts, THE ChartContainer SHALL call `createChart()` from Lightweight Charts and store the chart instance in a React ref.
3. WHEN the ChartContainer unmounts, THE ChartContainer SHALL call `chart.remove()` to dispose the Lightweight Charts instance and release all associated DOM resources.
4. WHEN the container's parent element resizes, THE ChartContainer SHALL call `chart.applyOptions({ width, height })` to resize the chart to match the new dimensions within 100 ms.
5. THE ChartContainer SHALL export a `useChartSeries` hook or equivalent mechanism that child components use to add and update series data without directly accessing the chart instance.

### Requirement 3: Candlestick Price Chart in StockDeepDive

**User Story:** As a trader, I want to see a candlestick price chart with volume bars for the selected symbol inside the StockDeepDive panel, so that I can visually assess price action and volume context alongside the AI signal.

#### Acceptance Criteria

1. WHEN a symbol is selected and the signal evaluation response is received, THE StockDeepDive SHALL render a CandlestickSeries chart displaying at least 60 OHLCV data points for the selected symbol.
2. THE StockDeepDive SHALL render a HistogramSeries below the CandlestickSeries on a separate price scale, displaying volume bars that correspond to each OHLCV candle.
3. WHEN the signal's `entry_zone.low` and `entry_zone.high` values are present, THE StockDeepDive SHALL render two horizontal price lines on the CandlestickSeries chart at those price levels, visually distinguishing the entry zone.
4. WHEN the signal's `stop_loss` value is present, THE StockDeepDive SHALL render a horizontal price line on the CandlestickSeries chart at the stop-loss price level using a distinct color (e.g., red).
5. WHEN the signal's `take_profit` value is present, THE StockDeepDive SHALL render a horizontal price line on the CandlestickSeries chart at the take-profit price level using a distinct color (e.g., green).
6. WHILE the signal data is loading (status is `"loading"`), THE StockDeepDive SHALL display a loading placeholder in place of the chart area and SHALL NOT attempt to render a Lightweight Charts instance with empty data.
7. IF the OHLCV data array is empty or unavailable, THEN THE StockDeepDive SHALL display an inline error message reading "Price data unavailable" in place of the chart.
8. THE StockDeepDive SHALL retain all existing text rows (Fundamentals %, Technical setup %, Sentiment %, Macro context, Entry zone, Rationale) below or alongside the chart.

### Requirement 4: Probability Distribution Chart in ExplainabilityPanel

**User Story:** As a trader, I want to see a visual probability distribution chart in the ExplainabilityPanel, so that I can quickly understand the modeled outcome probabilities (up, down, flat, tail loss) rather than reading raw percentages.

#### Acceptance Criteria

1. WHEN a signal response containing a `probability_distribution` object is received, THE ExplainabilityPanel SHALL render a HistogramSeries chart with four bars representing `up_5pct_20d`, `down_3pct_20d`, `flat_20d`, and `tail_loss_8pct_20d`.
2. THE ExplainabilityPanel SHALL label each bar with its scenario name and percentage value, rendered as chart markers or as an HTML legend adjacent to the chart.
3. THE ExplainabilityPanel SHALL color the `up_5pct_20d` bar green, the `down_3pct_20d` bar red, the `flat_20d` bar grey, and the `tail_loss_8pct_20d` bar orange.
4. WHILE the signal data is loading, THE ExplainabilityPanel SHALL display a loading placeholder in place of the distribution chart.
5. IF the `probability_distribution` object is absent from the signal response, THEN THE ExplainabilityPanel SHALL display the text "Distribution data unavailable" in place of the chart.
6. THE ExplainabilityPanel SHALL retain all existing driver score rows, key risks text, and source evidence text below or alongside the chart.

### Requirement 5: Agent Score Bar Chart in ExplainabilityPanel

**User Story:** As a trader, I want to see a bar chart of all seven AI agent contribution scores in the ExplainabilityPanel, so that I can understand which agents are driving the overall recommendation.

#### Acceptance Criteria

1. WHEN a signal response containing `component_scores` is received, THE ExplainabilityPanel SHALL render an AgentScoreChart displaying bars for all seven agents: `fundamentals`, `technical`, `news_sentiment`, `macro`, `alt_data`, `debate`, and `tax`.
2. THE ExplainabilityPanel SHALL label each bar with the agent name (with underscores replaced by spaces) and its score formatted as a percentage.
3. THE ExplainabilityPanel SHALL render bars with a length proportional to the agent score value on a 0–100% scale.
4. WHEN an agent score is at or above 0.68 (the BUY threshold), THE ExplainabilityPanel SHALL render that agent's bar in green. WHEN an agent score is at or below 0.38 (the SELL threshold), THE ExplainabilityPanel SHALL render that agent's bar in red. WHEN an agent score is between 0.38 and 0.68, THE ExplainabilityPanel SHALL render that agent's bar in the default neutral color.
5. IF `component_scores` is absent from the signal response, THEN THE ExplainabilityPanel SHALL display the text "Agent scores unavailable" in place of the AgentScoreChart.

### Requirement 6: Equity Curve Chart in BacktestViewer

**User Story:** As a quant analyst, I want to see the backtest equity curve as a line chart in the BacktestViewer, so that I can visually assess strategy performance over time rather than reading only summary statistics.

#### Acceptance Criteria

1. WHEN the walk-forward backtest response is received and the `equity_curve` array contains at least two values, THE BacktestViewer SHALL render an AreaSeries chart plotting the equity curve over the backtest period.
2. THE BacktestViewer SHALL label the Y-axis in USD and display the starting equity value ($100,000) and the final equity value as reference markers or axis ticks.
3. WHEN the final equity value is greater than the starting equity value ($100,000), THE BacktestViewer SHALL render the AreaSeries fill in green. WHEN the final equity value is less than or equal to the starting equity value, THE BacktestViewer SHALL render the AreaSeries fill in red.
4. THE BacktestViewer SHALL overlay trade entry and exit markers on the equity curve chart at the time-index positions corresponding to each entry in the `trades` array, using upward triangles for BUY trades and downward triangles for SELL trades.
5. WHILE the backtest data is loading, THE BacktestViewer SHALL display a loading placeholder in place of the equity curve chart.
6. IF the `equity_curve` array is absent or contains fewer than two values, THEN THE BacktestViewer SHALL display the text "Equity curve data unavailable" in place of the chart.
7. THE BacktestViewer SHALL retain all existing summary metric rows (annualized return, Sharpe ratio, Sortino/Calmar, benchmark excess, champion-challenger gate, journal entries) and the "Paper execute" button below the chart.

### Requirement 7: Portfolio Risk Metrics Visualization in PortfolioHealth

**User Story:** As a portfolio manager, I want to see portfolio risk metrics displayed as a visual bar chart in the PortfolioHealth panel, so that I can assess exposure and risk concentration at a glance.

#### Acceptance Criteria

1. WHEN the live risk evaluation response is received and contains a `metrics` object, THE PortfolioHealth SHALL render an AgentScoreChart-style horizontal bar chart displaying at minimum: VaR, CVaR, gross exposure, and net exposure as labeled bars.
2. THE PortfolioHealth SHALL normalize each metric bar relative to a defined maximum threshold (e.g., VaR and CVaR relative to total portfolio equity, exposures relative to 1.0) so that bars are visually comparable on a common scale.
3. WHEN `risk.kill_switch_required` is `true`, THE PortfolioHealth SHALL render all bars in red and display a "Risk breach" label in the panel header badge.
4. WHEN `risk.kill_switch_required` is `false`, THE PortfolioHealth SHALL render bars using a green-to-amber gradient based on proximity to each metric's threshold.
5. WHILE the risk data is loading, THE PortfolioHealth SHALL display a loading placeholder in place of the metrics chart.
6. IF the risk evaluation response is unavailable, THEN THE PortfolioHealth SHALL display the text "Risk data unavailable" in place of the chart.
7. THE PortfolioHealth SHALL retain all existing text rows (VaR/CVaR, next position size, trade impact) below the chart.

### Requirement 8: Stress Test Scenario Comparison Chart in StressTest

**User Story:** As a risk manager, I want to see a side-by-side bar chart comparing current portfolio value versus stressed portfolio value for each position in the StressTest panel, so that I can identify which holdings are most vulnerable under each scenario.

#### Acceptance Criteria

1. WHEN a stress-test response is received and the `positions` array contains at least one entry, THE StressTest SHALL render a grouped HistogramSeries or SVG bar chart with two bars per position: `current_value` (neutral color) and `stressed_value` (red if `pnl` is negative, green if `pnl` is positive).
2. THE StressTest SHALL label each position group with the `symbol` value and display the `pnl_percent` value as a data label on the stressed bar.
3. THE StressTest SHALL support rendering results for at least three simultaneous scenarios by providing a scenario selector (dropdown or tab) that re-runs the stress test via `runStressTest()` and updates the chart.
4. THE StressTest SHALL list the available scenarios by calling the `/stress-test/scenarios` endpoint and populating the scenario selector with the returned scenario names.
5. WHILE a stress-test scenario is loading, THE StressTest SHALL display a loading indicator on the chart area and SHALL disable the scenario selector to prevent concurrent requests.
6. IF the stress-test response is unavailable or the `positions` array is empty, THEN THE StressTest SHALL display the text "Stress test data unavailable" in place of the chart.
7. THE StressTest SHALL retain the existing summary rows (scenario name, total P/L, portfolio impact percentage) below the chart.

### Requirement 9: Mini Sparkline Charts in DiscoveryScanner

**User Story:** As a trader, I want to see a mini confidence sparkline or score bar for each result row in the DiscoveryScanner table, so that I can visually rank opportunities without reading individual percentage values.

#### Acceptance Criteria

1. WHEN the scanner returns results, THE DiscoveryScanner SHALL render an inline horizontal bar (progress-bar style or mini AreaSeries) in the Confidence column of each result row, proportional to the `confidence` value on a 0–100% scale.
2. THE DiscoveryScanner SHALL color each confidence bar green when `confidence` is at or above 0.68, amber when `confidence` is between 0.55 and 0.68, and red when `confidence` is below 0.55.
3. THE DiscoveryScanner SHALL render an inline directional indicator (e.g., ▲ for BUY, ▼ for SELL, — for HOLD) in the Signal column of each result row, using green for BUY, red for SELL, and grey for HOLD.
4. THE DiscoveryScanner SHALL retain the full existing table structure (Symbol, Signal, Confidence, Expected return rank, Reward/risk, Sector columns) and all existing filter controls.
5. IF the scanner returns zero results, THEN THE DiscoveryScanner SHALL display the existing "Run a scan to rank the universe." placeholder row without any chart elements.

### Requirement 10: Chart Theming and Accessibility

**User Story:** As a user, I want all charts to match the existing dark-themed dashboard and meet basic accessibility standards, so that the visual experience is consistent and usable.

#### Acceptance Criteria

1. THE Dashboard SHALL apply a dark background color (`#0d0d0d` or the existing CSS variable) and light text color to all Lightweight Charts instances via `createChart()` options.
2. THE Dashboard SHALL ensure all chart color choices (green, red, amber, grey) meet a minimum contrast ratio of 3:1 against the chart background, as required by WCAG 2.1 Level AA for non-text graphical elements.
3. THE Dashboard SHALL provide a text-based alternative (existing numeric rows or a `<caption>` / `aria-label`) for every chart so that the data is accessible to screen readers without relying solely on the visual chart.
4. WHEN a chart fails to render due to a JavaScript error, THE Dashboard SHALL catch the error via a React error boundary and display a fallback text message rather than crashing the entire panel.
5. THE Dashboard SHALL NOT introduce inline styles that override the existing `index.css` layout grid, ensuring all chart panels remain within the `.analysis-grid` and `.panel` CSS classes.
